# ATLAS API Contract (v1.1.0)

Source of truth: `contracts/openapi.json` (OpenAPI 3.1, 72 paths / 93 operations, generated by `python -m scripts.export_contracts`). Base path `/api/v1`. Live docs: `/docs`.

## Conventions
- **Success:** `{ "data": … , "meta": {page,page_size,total} }` (`meta` on lists only). **Errors:** `{ "error": { "code", "message", "details" } }` — always this shape, for every status.
- **Pagination** `?page=1&page_size=50` (max 200) · **Sorting** `?sort=-created_at` (column allow-list, 422 otherwise) · **Filtering** exact-match query params declared per endpoint in OpenAPI. IDs are UUID strings, timestamps ISO-8601 UTC. `DELETE` → 204.
- Secrets (`password_hash`, `credentials_encrypted`, tokens) are never returned except the one-time token responses below.

## Authentication (changed in 1.1.0 — see CHANGELOG)
`POST /auth/login {username,password,totp_code?}` → `{data:{access_token,refresh_token,token_type:"bearer",expires_in,user}}`.
Send `Authorization: Bearer <access_token>`. Access tokens are **opaque**, live **15 min**; renew with `POST /auth/refresh {refresh_token}`
(**rotates** both tokens; re-using an old refresh token revokes the session). `POST /auth/logout`, `/auth/logout-all`, `GET /auth/sessions`,
`GET /auth/me`, `POST /auth/change-password`, `POST /auth/mfa/{enroll,activate,disable}`, `POST /auth/password-reset/{request,confirm}`.
Admin: `POST|GET /auth/users`, `PATCH /auth/users/{id}`, `POST /auth/users/{id}/password-reset`, `DELETE /auth/users/{id}/mfa`, `GET /auth/audit-logs`.
Analyst+: `GET /auth/users/lookup?username=` (id/username/role only, for sharing).

## Authorization
Global role `viewer < analyst < approver < admin` **and** per-assessment permission `viewer < analyst < approver` (effective = the lower; admin bypasses).
- Assessment you are not a member of → **404 `not_found`** (existence not revealed), on the object *and* its children (assets, evidence, …) and in lists (filtered silently).
- Member with insufficient permission → **403 `insufficient_assessment_permission`**; insufficient global role → **403 `forbidden`**.
- Membership: `GET /assessments/{id}/members`, `PUT|DELETE /assessments/{id}/members/{user_id}` (owner, assessment-approver or admin). The owner cannot be changed (409 `owner_immutable`).
- `scope-rules` writes, assessment status changes and experiment approval need **approver** (assessment-level). Editing a target's `authorization_*` fields needs a global approver.

## Resources (CRUD where permitted; all list endpoints are access-filtered)
`targets`, `assessments`, `scope-rules`, `assets` (filters: `assessment_id, asset_type, scope_state, value`), `technologies`, `observations`, `evidence` (read-only + verify),
`application-routes`, `apis`, `databases` (+ `/databases/{id}/tables`), `database-tables`, `hypotheses`, `experiments`, `findings`, `reports`, `architecture`.

## Workflow endpoints
| Endpoint | Min role / assessment permission | Purpose |
|---|---|---|
| `POST /assessments/{id}/status` | approver / approver | draft→active→paused→completed→archived; activation needs valid authorization + an include rule |
| `POST /assessments/{id}/scope-check` | viewer / viewer | classify a host/URL: authorized / excluded / discovered |
| `POST /assessments/{id}/collect` | analyst / analyst | synchronous collection; out-of-scope hosts are skipped and audited |
| `POST /assessments/{id}/collect/jobs` → 202 `{job_id}` · `GET …/collect/jobs/{job_id}` | analyst / analyst · viewer | background collection; **authorization re-checked when the job executes** |
| `POST /assessments/{id}/internal/source` · `/schema` | analyst / analyst | authorized source / DDL analysis (size-capped) |
| `POST /assessments/{id}/architecture/build` · `GET /architecture?assessment_id=` | analyst · viewer | graph, every edge has `evidence_id` + `confidence` |
| `POST /assessments/{id}/ai/{agent}` | analyst / analyst | reconnaissance, architecture, application, security_research, evidence_validation, reporting |
| `POST /assessments/{id}/hypotheses/generate` | analyst / analyst | rule-based hypotheses |
| `POST /experiments/{id}/submit\|run\|rollback` · `approve\|reject` | analyst · **approver (not the requester)** | lifecycle; run re-checks scope; never follows redirects |
| `POST /evidence/{id}/verify` · `POST /findings/{id}/classify` | analyst (confirm: approver / approver) | human verification and classification |
| `POST /assessments/{id}/reports` · `GET /reports/{id}/html` | analyst · viewer | JSON report (stored) and HTML |

## Semantics the UI must respect
- `scope_state` is server-computed; `discovered` ≠ authorized. `observation.kind` ∈ direct_observation, inference, hypothesis, confirmed (human-only), unknown.
- `auth_required: null` on a route = **unknown**. Treat all evidence text as untrusted (escape it).
- Browser clients: CORS allows only the origins configured in `ATLAS_CORS_ORIGINS`; auth is header-based (no cookies).
